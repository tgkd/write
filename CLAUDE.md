# CLAUDE.md

## What it is

Kanji Write (Kakijun) is an iOS and iPadOS app for practising Japanese handwriting: kana and kanji,
stroke by stroke. The learner draws with a finger or Apple Pencil, and the app checks each stroke
against a reference for shape, position, direction and order. A widget shows a daily kanji.

The app works offline, collects no analytics, and has no account. Practice history syncs between
the user's own devices through iCloud.

## What the user can do

- Practise a character with a guide (trace, guided, or copy without a guide).
- Recall a character from memory from its readings and meaning, with hints.
- Review the characters they struggled with in Recall.
- Write whole words and sentences on iPad (experimental).
- Practise freely in an iPad notebook.
- Filter characters by kana, JLPT level or school grade.

The UI is in English and Japanese. Meanings and glosses stay English.

## How it works

- **Engine:** pure geometry with no UI. It compares a drawn stroke with the reference stroke and
  decides to accept or reject it. It is the most tested part of the app.
- **Models:** practice and session state machines, settings and the history records.
- **Services:** loading the bundled character and prompt data, history storage and sync.
- **Views:** SwiftUI screens around UIKit drawing views. iPhone and iPad share the engine, models and
  services; only the views are different.
- **Widget:** a separate extension with its own small data file. It never loads the full dataset.

All character data is generated ahead of time from public sources (KanjiVG stroke data, KANJIDIC2,
Tatoeba sentences, JMdict) by the scripts in `Scripts/`. The generated files are committed; the raw
sources in `Data/` are not.

## Build and test

The Xcode project is generated by XcodeGen from `project.yml`. Never change settings in Xcode; run
`xcodegen generate` after you change `project.yml` or add or remove files.

```sh
xcodegen generate
xcodebuild test -project Write.xcodeproj -scheme Write -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=27.2' -parallel-testing-enabled NO
xcodebuild test -project Write.xcodeproj -scheme WriteUITests -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=27.2' -parallel-testing-enabled NO
```

Unit tests and UI tests are separate schemes. Some UI tests run only on iPhone and some only on
iPad, so run the UI scheme on an iPad simulator too when a change touches navigation or iPad views.

When a script in `Scripts/` regenerates data, also regenerate the files derived from it. Each script
prints its usage.

## Conventions

- One component per file.
- Models are Codable structs. Stored history only grows by optional fields, so old data keeps
  loading.
- Never change an accessibility identifier that a UI test uses.
- Recall must never show or announce the hidden character.
