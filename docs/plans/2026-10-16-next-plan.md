# Kakijun: plan for the next cycle (2026-10-16)

Agreed with Codex in `.claude/duck/roadmap-next/`. Background research and the original top-10 are
in `.claude/notes/decisions/2026-10-16-competitors-and-roadmap.md`. This plan covers what to try
and in what order. It does not authorize any release.

## User decisions

- **Two things to try:** validation trust and a small word exercise.
- **No separate kids' app.** Instead, a correct dictionary filter by school grade, plus Japanese UI
  localization.
- **Start with the cheap check.**
- **No scheduled repetition.** Review stays a "characters you struggled with" list, with no due
  queue and no daily workload.
- **No personal lists.**
- **Sync** only if it turns out to be the simplest iCloud history sync between iPhone and iPad.
  Otherwise it is deferred.

## Phase 0: school data check (time-boxed evidence gathering)

### 0a. Coverage and grade membership

- **Grades 1–6.** The bundle's grades 1–6 hold 80/160/200/202/193/191 = 1,026 characters, the
  2020 配当表 counts. Count is not membership: compare the exact character set and grade
  assignment against the current official school list.
- **Bug to fix first.** 𠮟 (U+20B9F, jōyō) is missing from the bundle.
  `is_cjk_unified` in `Scripts/preprocess_kanjivg.py` accepts only U+4E00–9FFF and Extension A,
  so Extension B characters are dropped. Bundle grade 8 has 1,109 characters; the source XML has
  1,110.
  - Include supported curriculum characters deliberately. Don't widen the Unicode range blindly,
    since that would admit other Extension B entries.
  - Report the delta of generated characters.
  - Add a focused preprocessing regression test covering the intended inclusion and the existing
    exclusions.
  - Then regenerate `kanji_strokes.json` and the widget's `daily_kanji.json`.
- **Labels.** Grade 8 is not a school year. Label it "Other jōyō" / 常用漢字（小学校以外）, never
  "Grade 8".

### 0b. Stroke-order audit (scratch, not a permanent harness)

Bounded first pass: one working day, then a findings report and a scope decision.

- **Sources.** KanjiVG, as bundled, is the subject. The discrepancy detector is animCJK
  `graphicsJa.txt`: master as of 2026-10-16, 7,336 characters, sha256
  `00c4fc7a20cf6b615b9b67d9bc310e38945948e45d77a4b447f2e3255eef381d`. Pin the commit when running
  the check. animCJK only *detects* differences; it never decides who is right. It stays out of
  shipped data, which is our scope choice.
- **Method.**
  - Align whole characters with one uniform scale and translation, after checking the y-axis
    direction of both sources. Never normalize per stroke or squash x and y independently, because
    repeated horizontals would lose the evidence that separates their order.
  - Map each KanjiVG stroke to an animCJK median by assignment cost, and record the confidence
    margin.
  - Validate the mapper on a handful of known easy and known tricky characters before running all
    1,026.
- **Report.** Flag each of these separately:
  - missing coverage;
  - stroke-count differences;
  - ambiguous mappings;
  - direction reversals;
  - high residuals even when the assignment is identity;
  - confident permutations.
- **Review.**
  - Hand-check every flag, plus a small stratified sample of characters where the sources agree.
  - Classify each as: accepted alternative, KanjiVG defect, animCJK defect, mapper failure, or
    unresolved.
  - Decide cases against one credible, documented Japanese teaching reference, chosen and recorded
    during 0b. A school publisher's 筆順 table is the candidate:
    https://www.nichibun-g.co.jp/library/abc-series/shosha_abc_hitsujyun.pdf. It is not yet
    inspected. A case the reference can't resolve is marked unresolved.
  - KanjiVG's `-Kaisho` variant is not automatically the school form; the base file is the
    schoolbook style.
- **Fixes.** Apply proven defects in the generator through an override table, citing the reference
  that decided each one.
- **Exit criterion.**
  - The coverage and disagreement report is reproducible: script, source hashes and output are kept
    with the report.
  - Every decision is documented.
  - No unresolved material defect remains in the set the app presents as checked.
  - A large discrepancy set may indict the mapper rather than the data. If the method can't
    discriminate within the time box, report that uncertainty instead of forcing a result.

### 0c. Grade filter

- **Filters.** Add `CharacterFilter` cases for school grades 1–6 first. Add "Other jōyō" only after
  0a fixes coverage.
- **Picker.** All, Hiragana and Katakana stay reachable as today. Only the kanji grouping axis
  switches between JLPT (N5–N1) and School (grades 1–6).
- **Wiring.** Sessions use the selected pool, and Recall applies eligibility to that pool. A widget
  tap still opens its own character whatever filter is active. `PracticeLink` carries only a code
  point, so there is no filter-aware widget behavior.

### 0d. Localization and store page (a follow-on, not a prerequisite for Phases 1–2)

- **Japanese screens.** Prototype the key flow in Japanese with a String Catalog first, then decide
  on a full release.
- **Cues stay as they are.** UI language and cue language are independent. A Japanese UI keeps the
  English-meaning Recall cue for those who want it, and Recall is never silently turned off or
  reduced to readings by locale. Japanese-only, disambiguated cues arrive with Phase 2.
- **Store copy.** `docs/appstore-ja.txt` is stale: it still describes Study and Free modes. Update
  it when this ships, and keep the honest 「操作画面は英語です」 line until localization actually
  ships.
- **Measurement.** Record the baseline and release dates. App Store Connect impressions and
  downloads are exploratory signals, not a causal test. A test with an English UI measures the
  current offer, not demand for a localized app.

## Phase 1: validation trust

- **Capture corpus.**
  - Record a small set of finger and Pencil strokes, labelled correct or incorrect.
  - Keep timestamps, input type, coordinate space, and optional force and altitude.
  - Decide how refinements that arrive after `touchesEnded` are handled.
  - Measure false rejects and false accepts of the current validator first. That is the baseline.
- **Scale and proportion.**
  - Fit character scale and translation from accepted strokes, with an identifiability rule:
    bounded provisional scale, plus degeneracy handling for one-stroke characters, a tiny first
    dot, nearby centroids, consistently small characters, and one anomalously short stroke.
  - Never fit the scale to the stroke being judged.
  - No rotation.
  - Keep the fit consistent with hints, undo and the start marker.
- **Strictness.**
  - Decouple it from guide width. Today `AppSettings.derivedLeniency` scales the thresholds by
    about 0.78–1.67 across the 3…14 width range.
  - Expose an explicit strictness choice calibrated on the corpus, and migrate each user's current
    effective value.
  - Store the grading config and version with each record.
  - "Strict" never rejects legitimate handwriting variants.
- **Miss evidence.**
  - Record independent detector flags on rejections: shape failed, position failed, or not
    evaluated (centroid prefilter).
  - These describe the detector, not the user's memory. Hints and retries still populate
    "struggled with", with no blanket exemption for position-only misses.
  - A rejection the user explicitly disputes can be excluded from Review under a documented policy.
    Old records keep decoding with their old meaning.
- **Exit criterion.**
  - **Baseline:** the current validator at equivalent effective threshold settings, including each
    migrated setting, on the same labelled captures.
  - **Held-out data:** keep a small held-out subset, split by writer or session where feasible, so
    tuning and reporting never use the same examples.
  - **Reporting:** report counts as well as rates. A small corpus says nothing about population
    accuracy.
  - **Pass condition:** the targeted scale and proportion cases improve, with no material
    false-accept regression. Changing guide width no longer changes any validation result.
  - **Strictness policy:** "Strict never rejects legitimate variants" is the intended policy, not a
    measured zero-error guarantee.

## Phase 2: "write the missing kanji" (word pilot)

- **Set.** A fixed list of about 20–30 hand-reviewed prompts. No JMdict infrastructure.
- **Prompt.**
  - A curated sentence with the target word replaced by kana or a blank, plus an optional English
    gloss. Kana alone is ambiguous, so context is mandatory.
  - Never show the target kanji under furigana.
  - Okurigana is shown; the user writes only the kanji slots.
- **Answers.** Only reviewed spellings or explicitly listed alternatives count. Record the excluded
  homophones and variant spellings in the curation notes.
- **Data model.** Stable word, item and slot IDs, with ordered targets. A completed word is recorded
  separately from character records. Context-cued success never clears a character's standalone
  Recall struggle.
- **Familiarity.** A word built from grade-1–2 kanji isn't necessarily a grade-1–2 word. Curate
  vocabulary familiarity separately.
- **Audience.** One format serves both: L2 learners use the gloss, Japanese users use the sentence.
- **Exit criterion (acceptance checks, not a research programme).**
  - All 20–30 prompts have supported target glyphs, disambiguating context and declared answers.
    No target kanji is visible before a reveal.
  - On iPhone and iPad, these work: multi-slot completion, retry and reset, and shown okurigana.
  - Word records stay separate, and standalone Review is unchanged by word success.
  - Learning efficacy and curriculum suitability remain unproven.

## Phase 1b: finger brush — jitter and start/end hooks (added 2026-10-16, user request)

- **Hooks:** trim the start and end hooks that finger contact creates. These are sharp direction
  reversals in the first and last few points, caused by the contact patch growing on touch-down and
  the finger rolling on lift. Trim them before both rendering and validation, with conservative
  limits so real short strokes, dots and hane/harai are kept.
- **Jitter:** reduce it. Smoothing is chosen by input type (finger is noisier than Pencil), and the
  Smoothing setting gains an Auto default.
- **Finger width:** a finger has no force data, so speed alone made every stroke the maximum width
  with blunt ends. Give finger strokes a short press-in, gentle thinning toward the end, and properly
  tapered, rounded tips.
- **Grading input:** validation gets the hook-trimmed points, filtered with fixed parameters, so the
  user's Smoothing setting can no longer change the grade.
- **No shape auto-correction:** the learner's ink is never snapped to the reference.
- **Exit check:** unit tests on synthetic hooked and jittered strokes, plus a simulator look. Tuning
  on real finger captures is still open; recording them needs `-captureStrokes`.

## Later, scoped follow-ons (no order implied)

- **Rejection feedback** that shows evidence before a label. Direction comes from a reversed-path
  comparison against the expected stroke. Start-point advice is a separate diagnosis, and short or
  symmetric strokes are allowed to stay uncertain.
- **Completed-character comparison and replay:** the learner's ink over the model, with no numeric
  score. This is where a reference stroke-ending style can be taught; endings are never graded.
- **Performance:** measure cold launch, Home recompute and history writes, then fix whatever is
  demonstrably slowest.
- **Recall cue configuration:** reading-first layout with the same information; audio added on top,
  never replacing anything.
- **iCloud history sync, behind a short feasibility check.**
  - Candidate: CloudKit private database, one record per immutable `PracticeRecord`, merged as a
    union by ID.
  - Still needed: a deterministic tie-break for "latest run per character" (`PracticeStats`
    groups by latest `completedAt`), dedup, offline retry, and a no-account state.
  - History only. No settings sync, no general event-sourcing project.
  - If the check shows it isn't simple, defer it.

## Dropped

- Scheduled repetition and due queues.
- Personal lists and WaniKani or Anki import.
- A separate kids' app.
- Handwriting lookup.
- Graded stroke endings.
- A general JMdict word curriculum.

## Implementation status (2026-10-16, branch `fanout/next-plan`)

- **Phase 1, done in code:**
  - **Scale fit.** Copy and Recall fit a bounded scale plus translation from prior anchors
    (identity below 2 anchors or when the anchors are too close together; clamped to 0.6–1.6;
    confidence-blended). The reference layer gets the same transform.
  - **Evidence and proportion.** Per-stroke evidence flags are recorded. The proportion check
    rejects only at Strict.
  - **Strictness.** It is a persisted setting, migrated from the guide width, and guide width is
    invariant for grading.
  - **Miss evidence, disputes and Review.** Miss evidence and disputes are stored on records.
    Review drops disputed misses and keeps everything else.
  - **Capture.** `-captureStrokes` writes raw captures.
- **Phase 1 measurements:** these are synthetic, not human handwriting. On the held-out half of
  the synthetic corpus:

  | Case | Before | After |
  |---|---|---|
  | 0.7× character, false rejects at Normal | 121/388 | 17/388 |
  | 1.2× character, false rejects at Normal | 21/388 | 2/388 |
  | False accepts at Normal | 108/1440 | 116/1440 (all extra are truncated strokes) |
  | Truncated strokes accepted at Strict | 59/360 | 5/360 |

  The plan's exit criterion is not met: there is no human-labelled corpus yet, and the strictness
  levels are initial defaults, not calibrated.
- **Phase 1b, done:**
  - **Hooks.** Hook trimming happens before both rendering and validation. The window is 3.5% of
    the canvas, 5–12pt, and capped at 8% of the stroke length.
  - **Validation input.** Validation runs on raw points with fixed filtering, independent of the
    Smoothing setting.
  - **Smoothing.** Auto is the default (finger heavier, Pencil medium).
  - **Finger ink.** Finger strokes have a width profile with fine, round-capped tips; Pencil keeps
    its pressure model and gains round caps.
  - **Checked by** offline renders on synthetic hooked strokes. Real finger captures were not
    checked.
- **Phase 2, done:**
  - **Prompts.** 24 prompts use Tatoeba/Tanaka sentences (CC BY 2.0 FR, credited in Settings),
    turned into kana with Tatoeba's furigana. The Tatoeba ids are kept in the notes. Codex
    reviewed them (AI review, not native or teacher review).
  - **Records.** Word records are separate from character history.
  - **iPad.** The iPad check is not done; only an iPhone simulator is available.
- **0d localization, done:**
  - **Coverage.** Japanese String Catalogs cover the app (122 keys) and the widget (4 keys).
    Meanings and glosses stay English.
  - **Store copy.** The 1.8 copy is in `docs/appstore-ja-1.8.txt`.
  - **Checked by** screenshots of the Japanese and English UI on iPhone 17 Pro.
- **Hook window retuned:** from at most 6pt to 5–12pt (3.5% of the canvas). The old window trimmed
  none of the realistic 8–9pt finger hooks in synthetic tests.
- **Pre-existing, not fixed:** `RecallUITests.testCompletedPracticeIsRecordedButNotSentToReview`
  fails on master too, so it is not caused by this branch. Fix it separately.
- **Follow-ups:**
  - `CFBundleDisplayName` is not localized.
  - Icon-only buttons have no accessibility labels.
  - `WordRecord.misses` does not subtract disputes.
- **Tests:** the merged wave 1 passes the full unit suite (371 tests, also after localization) on iPhone 17 Pro · iOS 27.0.
