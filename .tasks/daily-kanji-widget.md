# Task: Add a "Daily Kanji" home and lock screen widget that opens practice on that kanji

## Goal
A new WidgetKit extension shows one JLPT kanji per calendar day on the Home Screen (small, medium)
and the Lock Screen (rectangular, circular), on iOS 16 and later. Every size shows the same kanji on
the same local day, and it changes at local midnight. Tapping the widget opens the app through
`kakijun://practice?cp=<codePoint>` straight into practice for that kanji on iPhone and iPad, from a
cold launch or from any screen.

## Context

  Xcode 27. `project.yml` is the source of truth. `Write.xcodeproj` and `Write/Info.plist` are
  generated by `xcodegen generate` and ARE committed. Running `xcodegen generate` on the current
  tree reproduces them with no diff. Never edit the `.xcodeproj` or a generated `Info.plist` by hand.
- Targets today: `Write` (application, bundle id `com.j.write`, sources `Write`, resources
  `Write/Resources`, `DEVELOPMENT_TEAM: ULU867Y7LC`, automatic signing, `TARGETED_DEVICE_FAMILY
  "1,2"`) and `WriteTests` (`bundle.unit-test`, sources `WriteTests`, depends on `Write`, extra
  resource `Write/Resources/kanji_strokes.json`). Tests use `@testable import Write`, so any Swift
  file compiled into the `Write` target is testable. There is no widget, App Group, entitlements file
  or URL scheme today.
- `MARKETING_VERSION: "1.5"` and `CURRENT_PROJECT_VERSION: "51"` currently sit in the `Write`
  target's settings. An embedded extension must carry the same version and build as its app, or App
  Store validation rejects the upload.
- `Write/Resources/kanji_strokes.json` is 22 MB: an object keyed by lowercase hex code point with
  no leading zeros (`"5c71"`). Each value has `codePoint`, `element`, `strokes` (array), `components`,
  and optional `onYomi`, `kunYomi`, `meanings` (arrays of strings), `grade`, `jlpt` (1–5), `freq`,
  `romaji`. `KanjiDataStore.init(bundle:)` decodes all of it eagerly, so the widget extension must
  never contain that file or `KanjiDataStore`.
- Measured on the committed JSON: 6557 entries, 2210 with a `jlpt` level — N5 79, N4 166, N3 367,
  N2 367, N1 1231. Every one of the 2210 has at least one meaning and at least one stroke; 8 have no
  `onYomi`, 383 have no `kunYomi`, none has neither. Kun readings are in KANJIDIC2 notation
  (`ひと-`, `い.く`); the app displays them verbatim, and so does the widget. A compact JSON array of
  those 2210 entries with the fields in Plan step 1 is about 292 KB.
- The only script language in `Scripts/` that is used is Python 3 (`preprocess_kanjivg.py`: plain
  `sys.argv` parsing, `json.dump(..., ensure_ascii=False, separators=(",", ":"))`, `sys.exit(msg)`
  on a contract failure). `Scripts/preprocess_kanjivg.swift` is unused. Python here is 3.14.
- The app is English only: no `.lproj`, no `String(localized:)`, all UI strings are literals.
- Navigation in `Write/App/ContentView.swift`:
  - `body` picks `iPadLayout` when `horizontalSizeClass == .regular`, else `iPhoneLayout`.
  - iPhone: `NavigationStack` with NO path binding. `KanjiPickerView` pushes
    `NavigationLink(value: kanji.codePoint)` (a `String`) and its ▶ button pushes a `SessionRoute`
    (`Write/Models/SessionState.swift`). Destinations: `String` → `PracticeView(kanjiData:)`,
    `SessionRoute` → `SessionPracticeView`. The stack is heterogeneous, so a `NavigationPath` (not
    `[String]`) is needed to drive it.
  - iPad: `NavigationSplitView`. The sidebar `KanjiPickerView` writes `@State selectedCodePoint:
    String?`. The detail column is `NavigationStack(path: $iPadNavigationPath)` (a `NavigationPath`)
    whose root is `KanjiDetailView` for the selection; its `onPractice` appends
    `PracticeRoute(codePoint:)` and `onNotebook` appends `NotebookRoute` and sets
    `columnVisibility = .detailOnly`. `.onChange(of: selectedCodePoint) { _ in iPadNavigationPath =
    NavigationPath() }` clears the detail stack on every selection change. That handler runs AFTER
    the update that changed the selection, so a deep link that sets the selection and appends a route
    in one go has its route wiped. It also does not fire when the selection is unchanged.
  - `dataStore.lookup(codePoint:)` lowercases its argument; keys are lowercase hex.
- WidgetKit on iOS 16: `StaticConfiguration` + `TimelineProvider`; families `.systemSmall`,
  `.systemMedium`, `.accessoryRectangular`, `.accessoryCircular` all exist on 16.
  `containerBackground(for:)` is iOS 17+, and on iOS 17+ a widget that does not call it renders
  a "please adopt containerBackground API" placeholder instead of its content. On iOS 17+ the system
  also adds content margins itself; on iOS 16 it does not. `widgetURL(_:)` works for all four families
  on iOS 16.
- Baseline: the full suite passes, 177 tests, 0 failures, with the Acceptance test command. No
  signing override is needed for the simulator. `build/` is gitignored.

## Plan
1. `Scripts/build_daily_kanji.py`: usage `python3 Scripts/build_daily_kanji.py <kanji_strokes.json>
   <output.json>`; print a usage line to stderr and exit 1 on a wrong argument count, like
   `preprocess_kanjivg.py`.
   - Keep every entry whose `jlpt` is present.
   - Emit a JSON array. Each element has, in this key order: `codePoint`, `character`
     (`chr(int(codePoint, 16))`), `meanings` (the first two, or one if there is only one),
     `onYomi` (first on reading, key omitted if none), `kunYomi` (first kun reading, key omitted if
     none), `strokeCount` (`len(strokes)`), `jlpt`.
   - Order the array by `hashlib.sha256(codePoint.encode()).hexdigest()`. This is the fixed
     "shuffle" the widget walks one per day. A hash order was chosen over `random.shuffle` with a
     seed because it does not depend on the Python version, and over code-point order because that
     would walk radicals in sequence and cluster N1 runs.
   - Exit non-zero via `sys.exit` with a message naming the characters if any kept entry has no
     meanings.
   - Write with `ensure_ascii=False, separators=(",", ":")`. Print one summary line with the total
     and the per-level counts.
   - No docstring and no comments.
2. Run `python3 Scripts/build_daily_kanji.py Write/Resources/kanji_strokes.json
   WriteWidget/Resources/daily_kanji.json` (2210 entries, about 292 KB).
3. `Shared/DailyKanji.swift`: `struct DailyKanji: Codable, Equatable, Hashable, Sendable` with
   `codePoint: String`, `character: String`, `meanings: [String]`, `onYomi: String? = nil`,
   `kunYomi: String? = nil`, `strokeCount: Int`, `jlpt: Int`. Add computed `primaryMeaning: String`
   (`meanings.first ?? ""`) and `strokeCountLabel: String` ("1 stroke" / "\(n) strokes").
4. `Shared/DailyKanjiCatalog.swift`: `enum DailyKanjiCatalog` with `static func load(from bundle:
   Bundle) -> [DailyKanji]`. It reads `daily_kanji.json` from the bundle, returns `[]` if the file is
   missing or fails to decode, and never traps.
5. `Shared/DailyKanjiPicker.swift`: `struct DailyKanjiPicker: Sendable`,
   `init(entries: [DailyKanji], calendar: Calendar)`.
   - `func dayNumber(for date: Date) -> Int`: whole days from the calendar's start of day of
     2026-01-01 to the calendar's start of day of `date`, computed with
     `calendar.dateComponents([.day], from:to:)`. The epoch is built with
     `calendar.date(from: DateComponents(year: 2026, month: 1, day: 1))`, so day boundaries are local
     midnights in that calendar's time zone and DST days count as one day. Negative for dates before
     the epoch.
   - `func kanji(for date: Date) -> DailyKanji?`: `nil` if `entries` is empty. Otherwise the entry at
     the non-negative modulo of `dayNumber` by `entries.count` (`((n % c) + c) % c`).
   - `func timelineDates(from date: Date, days: Int) -> [Date]`: `[date]` followed by the start of
     each of the next `days - 1` days.
   These live in `Shared/`, compiled into both the app and the extension, so `WriteTests` can test
   them through `@testable import Write` without a test dependency on the extension.
6. `Shared/PracticeLink.swift`: `enum PracticeLink` with:
   - `static let scheme = "kakijun"`;
   - `static func url(codePoint: String) -> URL`: `kakijun://practice?cp=<codePoint>`, built with
     `URLComponents`;
   - `static func codePoint(from url: URL) -> String?`: non-nil only when the scheme is `kakijun`
     and the host is `practice` (both case-insensitive), and a `cp` query item holds 1–6 hex digits.
     Return it lowercased. It does not check that the kanji exists; `ContentView` does.
